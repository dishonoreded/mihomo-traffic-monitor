# Domain Docs

This is a single-context repository.

## Before Exploring

Read `CONTEXT.md` at the repository root and the relevant decisions under
`docs/adr/`. If a document does not exist yet, continue silently.

## Vocabulary

Use the glossary's canonical terms in issues, specifications, tests, code,
and user-facing explanations. Do not drift to synonyms that the glossary
explicitly avoids. If a required concept has no definition, record the gap
for domain modeling rather than inventing ambiguous language.

## Decisions

Read ADRs that affect the area being changed. Surface conflicts explicitly;
never override an accepted ADR without recording a superseding decision.
